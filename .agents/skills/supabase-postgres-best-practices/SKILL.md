# Supabase Postgres Best Practices

Comprehensive performance optimization guide for Postgres, maintained by Supabase. Contains rules across 8 categories, prioritized by impact to guide automated query optimization and schema design.

## Trove repository application boundary

For Trove application work, also follow the repository root `AGENTS.md` and `.agents/skills/trove-app-building/SKILL.md`.

- The Python API owns database access, authorization, business rules, and transactions. The mobile app must not query Postgres or Supabase's Data API directly.
- Define integrity, ownership, and acknowledgement semantics in the API/domain contract. Do not duplicate database decision logic in screens or use client defaults as authorization.
- Do not change schemas, policies, privileges, or transaction guarantees to disguise an upload/network/credential failure. Diagnose the actual failing boundary first.
- Keep one intended persistence path. Preserve stable operation identity and use explicit transactions where related changes must commit together; do not add alternate databases or silent compatibility writes.

## When to Apply

Reference these guidelines when:
- Writing SQL queries or designing schemas
- Implementing indexes or query optimization
- Reviewing database performance issues
- Configuring connection pooling or scaling
- Optimizing for Postgres-specific features
- Working with Row-Level Security (RLS)
